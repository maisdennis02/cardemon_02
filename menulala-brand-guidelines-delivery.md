# Brand Guidelines — Apps de Delivery para Integração no menulala

Guia consolidado pra implementar botões "Pedir pelo [App]" no menulala respeitando as regras de marca de cada plataforma.

---

## Regra geral pra todos os apps

Em quase todos os casos, as plataformas permitem que o restaurante (parceiro deles) exiba o logo do app pra indicar disponibilidade. Você, como menulala, está exibindo essa indicação **em nome do restaurante** — então o uso é coberto.

Princípios universais que aparecem em **todas** as guidelines:

- **Não modifique o logo**: nada de esticar, rotacionar, mudar cor, adicionar efeito, filtro, sombra, gradiente.
- **Margem mínima de respiro**: deixe espaço ao redor do logo (cada app define o seu, mas a regra geral é "altura do logo equivalente em todos os lados").
- **Contraste de fundo**: use a versão clara em fundos escuros e a versão escura em fundos claros.
- **Tamanho mínimo legível**: nunca tão pequeno que vire mancha.
- **Não dê impressão de endosso/parceria oficial** se você não for parceiro contratual. Indicar "disponível em [App]" é diferente de "endossado por [App]". O primeiro é permitido, o segundo não.
- **Não combine com logo de concorrente no mesmo lockup**: cada botão é independente, não junte iFood + Rappi no mesmo selo, por exemplo.

## 1. iFood (Brasil)

### Onde baixar
- Guia oficial: blog-parceiros.ifood.com.br (busque "Guia de Identidade Visual")
- Logos PNG/SVG: imagensfree.com.br/ifood-logo-png ou contato com iFood pra material oficial

### Regras de uso
- **Grafia correta** do nome: "iFood" ou "iFOOD". Errado: "ifood", "IFOOD", "Ifood". O "i" é sempre minúsculo, o "F" sempre maiúsculo.
- **Cores oficiais**:
  - Vermelho iFood: `#EA1D2C`
  - Branco
- **Versões disponíveis**:
  - Logo vermelho sobre fundo branco/claro (principal)
  - Logo branco sobre fundo escuro
  - Sobre fundos coloridos: versão monocromática
- **Margem mínima**: equivalente ao dobro da largura da base da letra "i" pra cada lado.
- **Logo "Sorriso"** (símbolo das duas letras "O" + seta): é marca secundária. Só use depois que o consumidor já teve contato com a marca principal. Bom pra rodapé, badge pequeno, etc.

### Recomendação pro menulala
Use a versão horizontal vermelha com texto, em fundo branco/claro. Texto do botão: **"Pedir no iFood"**.

## 2. Uber Eats (Global)

### Onde baixar
- Página oficial pública: `merchants.ubereats.com/us/en/resources/learning-center/co-marketing-tools/`
- Versões pra parceiros (com senha): contato em `merchants@uber.com`

### Regras de uso
Uber Eats tem **as guidelines mais explícitas e públicas** dos três. Cobre exatamente o seu caso de uso.

- **Cores oficiais**:
  - Preto
  - Branco
  - Uber Eats green: `#06C167`
- **Versões disponíveis**:
  - Wordmark horizontal (paisagem)
  - Wordmark vertical/empilhado (quadrado ou retrato)
  - **"Order with" badge** — este é o ideal pro seu caso, é um selo pronto pra ser exibido em materiais de parceiro
  - App icon (para indicar download)
- **Onde usar cada cor**:
  - Fundo escuro: logo branco
  - Fundo claro: logo preto
  - Verde Uber Eats: só no app icon, badges web e sacolas de entrega (não no logo geral)
- **Lockup com logo do parceiro** (relevante pra você): o logo do parceiro vem primeiro e domina visualmente. Uber Eats fica em papel de apoio. Separador entre os dois = linha vertical com espaçamento equivalente à largura do "U" de Uber.
- **Proibido**:
  - Usar wordmark de duas cores antigo
  - Escalar, esticar, rotacionar, inclinar
  - Texto ou elementos dentro do espaço de respiro
  - Mudar cor
  - Filtros estilizados
  - Integrar o logo dentro de uma frase

### Recomendação pro menulala
Use o badge **"Order with Uber Eats"** ou versão equivalente em português (verifique se existe). Texto do botão se for customizado: **"Pedir no Uber Eats"**.

## 3. DoorDash (EUA)

### Onde baixar
- Brand assets via Brandfetch: `brandfetch.com/doordashstore.com`
- Material pra parceiros: portal do merchant DoorDash
- Logos não-oficiais: gdgraphic.com (várias versões SVG/PNG)

### Regras de uso
DoorDash **não publica brand guidelines públicas detalhadas** como o Uber Eats. As regras vêm via portal de parceiros (Merchant Suite).

- **Cores oficiais**:
  - Vermelho DoorDash: `#EB1700` (também aparece como `#FF3008` em algumas referências)
  - Branco
  - Cinza
- **Logo**: D estilizado em vermelho + wordmark "DoorDash" sans-serif.
- **Versões disponíveis**:
  - Vermelho sobre fundo claro (principal)
  - Branco sobre fundo escuro
  - Preto monocromático (uso minimalista)
- **Regra explícita**: "Se você não é afiliado ao DoorDash, evite usar de forma que sugira endosso ou parceria". Usar pra indicar disponibilidade do restaurante é OK.

### Recomendação pro menulala
Use a versão horizontal vermelha com wordmark completo. Texto do botão: **"Order on DoorDash"**.

## Resumo executivo: como tratar isso no produto

### Estrutura de dados sugerida por restaurante

Cada restaurante no menulala tem um campo `delivery_links` que é uma lista de objetos:

```
{
  "platform": "ifood",  // ifood, ubereats, doordash, rappi, grubhub, pedidosya, didifood
  "url": "https://www.ifood.com.br/delivery/...",
  "active": true,
  "display_order": 1
}
```

### Componente de botão

Pra cada plataforma, mantenha no front:

- SVG do logo (versão clara + escura)
- Cor de fundo (cor oficial do app, ou branco com borda)
- Cor do texto
- Texto localizado (PT / EN / ES)

### Regras de implementação

1. **Hierarquia visual**: o logo do **restaurante** vem primeiro (no topo do cardápio). Os botões de delivery são secundários, agrupados numa seção tipo "Também disponível em" ou "Pedir para entrega".
2. **Validação de URL**: regex por plataforma pra evitar dono colar URL errada.
3. **Universal links**: use a URL canônica de cada plataforma — iOS/Android abrem o app nativo automaticamente se instalado.
4. **Tracking**: adicione UTM nas URLs antes de redirecionar pra você saber quantos cliques vão por plataforma.
5. **Ordem padrão por região**:
   - Brasil: iFood → Rappi → Uber Eats → 99Food
   - EUA: DoorDash → Uber Eats → Grubhub
   - LatAm hispano: Rappi → PedidosYa → DiDi Food → Uber Eats

### Texto recomendado pro botão (não usar "Powered by [App]")

- **PT-BR**: "Pedir no [App]" ou "Disponível no [App]"
- **EN**: "Order on [App]" ou "Available on [App]"
- **ES**: "Pedir en [App]" ou "Disponible en [App]"

---

## Risco a considerar

Você não tem contrato de parceria com nenhum desses apps. O uso permitido é o do **restaurante parceiro deles** sinalizando disponibilidade. Como o menulala é só o intermediário visual (o restaurante cola a URL dele próprio), o uso é defensável.

Se algum dia escalar muito e quiser segurança extra, vale entrar em contato com cada app pra registrar o menulala como ferramenta de parceiro (vários têm programas de "tech partner"). Mas isso não é bloqueador pro lançamento da feature.
